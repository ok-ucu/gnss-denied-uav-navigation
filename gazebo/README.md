
# Gazebo-симуляція, камера та IMU (Людина 2)

Середовище **Gazebo Harmonic у Docker (ROS 2 Jazzy)** з віртуальним дроном, камерою, спрямованою вниз, та IMU.

У межах Фази 1 реалізовано симуляцію сенсорів, передавання даних через ROS 2 bridge, керування рухом моделі та перевірку optical flow.

**Статус:** Фаза 1 протестована. Повна інтеграція руху ArduPilot SITL → Gazebo виконується окремо та не входить до підтверджених результатів цього етапу.

---

## Результати перевірок Фази 1

### 1. Камера та IMU

Сенсорні потоки перевірено під час роботи симуляції.

| Параметр | Цільове значення | Виміряний результат |
|---|---|---|
| Частота камери | 30 FPS | ~27 FPS |
| Частота IMU | 200 Гц | ~189 Гц |
| Роздільність камери | 640 × 480 | 640 × 480 |

Виміряні частоти можуть відрізнятися від заданих через продуктивність симуляції та програмний рендеринг.

### 2. ROS 2 bridge та рух моделі

Перевірено передавання даних через ROS 2 bridge та керування моделлю `camera_drone` за допомогою топіка:

`/model/camera_drone/cmd_vel`

Під час тестування координата X моделі змінилася з приблизно 18.308 м до 34.529 м, що підтверджує реакцію моделі на команди руху.

Ця перевірка стосується керування через ROS 2, а не повного замкненого контуру керування ArduPilot SITL.

### 3. Регресійний тест

Регресійний тест запускається через `pytest` і перевіряє показники відстеження ознак на тестових даних.

**Результат: PASS.**

Команда запуску з кореня репозиторію:

```bash
python -m pytest gazebo/test_regression.py -v -s
```

Тест перевіряє такі пороги:

- `tracking_ratio >= 85%`
- `mean_inliers >= 30`

### 4. Optical flow

Для перевірки якості текстури поверхні та відстеження характерних точок використано алгоритм Lucas–Kanade з додатковою перевіркою відповідностей.

Команда запуску з кореня репозиторію:

```bash
python gazebo/verify_optical_flow.py \
  --dataset recordings/sample_flight \
  --min-inliers 50 \
  --out-img gazebo/optical_flow_verification.png
```

**Фактичний результат:**

| Показник | Значення |
|---|---|
| Мінімальна кількість inliers | 50 |
| Знайдено inliers | 298 |
| Статус | PASS |
| Ілюстрація | `gazebo/optical_flow_verification.png` |

Кількість знайдених inliers перевищує встановлений поріг у 5.96 раза.

Це підтверджує придатність перевіреної послідовності кадрів для відстеження характерних точок. Стабільність повної VIO-навігації перевіряється окремо.

## Швидка перевірка без запуску симулятора

Команди виконуються з кореня репозиторію.

Для Python-тестів необхідні відповідні залежності, зокрема `pytest`, `numpy` та `opencv-python`.

### Регресійний тест

```bash
python -m pytest gazebo/test_regression.py -v -s
```

### Перевірка optical flow

```bash
python gazebo/verify_optical_flow.py \
  --dataset recordings/sample_flight \
  --min-inliers 50 \
  --out-img gazebo/optical_flow_verification.png
```

### Додаткові діагностичні скрипти

Із каталогу `gazebo/`:

```bash
python3 check_gazebo_stream.py --mock --duration 2.0
python3 verify_sync_axes.py
```

Режим `--mock` використовує тестові дані та не замінює перевірку реальних сенсорних потоків у Gazebo.

## Межі відповідальності та статус інтеграції

**Фаза 1 (Gazebo, камера, IMU):**

Реалізовано та перевірено симуляцію сенсорів, ROS 2 bridge, рух моделі через ROS 2, регресійний тест та optical flow.

**Фаза 2 (ArduPilot SITL → Gazebo):**

Інтеграція телеметрії автопілота з рухом моделі Gazebo перевіряється окремо. Наявність MAVLink-телеметрії сама по собі не підтверджує повної синхронізації руху.

**VIO та GNSS-denied навігація:**

Інтеграція оцінки положення від VIO з ArduPilot EKF3 та перевірка навігації без GNSS належать до наступних етапів командного проєкту.
